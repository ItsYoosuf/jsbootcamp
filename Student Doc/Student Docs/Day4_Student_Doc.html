Topic 1 The if Statement if (condition) { ... }

VISUAL REFERENCE

Syntax:   if (condition) { ...code to run if true }
Rule:   If the condition is true, the block runs. If false, skipped.
Always use curly braces — even for one-liners. Skipping them causes bugs when you later add a second line.

Topic 2 if / else if / else Decision chains for ranges

VISUAL REFERENCE

Order matters: JS stops at the FIRST true condition. Always order from most specific to least specific.
⚠️ Common bug: Writing marks >= 60 before marks >= 90 — the second is unreachable because 90 is also >= 60.

Topic 3 Nesting & Why to Avoid It Code that drifts right is a smell
The pyramid of doom: putting if inside if inside if. Allowed, but hard to read. Each level pushes code right and adds mental effort. 
// Hard to follow:
if (user) {
  if (user.isActive) {
    if (user.age >= 18) {
      console.log("Access granted");
    }
  }
}

We'll fix this with guard clauses in Topic 6.

Topic 4 switch Statement Many exact-match values, one variable

VISUAL REFERENCE

Use when: comparing ONE variable to many exact values (day name, status code, role).
3 keywords:   case (match),   break (exit),   default (fallback).
⚠️ Forget break → fall-through! Execution continues into the NEXT case. The #1 switch bug.

Topic 5 Truthy & Falsy (DEEP) The 6 falsy values — memorise!

CRITICAL — MEMORISE THIS

The 6 falsy values:
  1. false    2. 0    3. "" (empty string)    4. null    5. undefined    6. NaN

Topic 6 Guard Clauses — Clean Code Flatten nested conditions with early return
The pattern: handle invalid cases at the top with return. The "happy path" sits at the bottom with zero indentation. 
// BEFORE — nested:
function checkAccess(user) {
  if (user) {
    if (user.isActive) {
      if (user.age >= 18) {
        console.log("Access granted");
      }
    }
  }
}

// AFTER — guard clauses:
function checkAccess(user) {
  if (!user) return;
  if (!user.isActive) return;
  if (user.age < 18) return;

  console.log("Access granted");
}
Habit: every time you write if inside if inside if, ask yourself — can I flip and return early?

PART 3 — VISUAL SUMMARY

if / else if / else

Pattern When to use
if (cond) { } Simple yes/no decision
if / else Two-way choice
if / else if / else Multiple ranges or conditions
Guard clause if (!x) return; Flatten nested conditions

switch

Keyword Purpose
case x: Match value with ===
break; Exit switch (don't forget!)
default: Catch-all (like else)
Stacked case Group cases (intentional fall-through)

Truthy & Falsy

Falsy (only 6) Truthy (everything else)
false "0" (string)
0 [] (empty array)
"" (empty string) {} (empty object)
null " " (space)
undefined "false" (string)
NaN any non-zero number

Choosing Your Tool

Scenario Use
One condition, simple action if
Two paths if / else or ternary
Multiple ranges if / else if / else
One variable, many exact values switch
Many nested checks guard clauses
